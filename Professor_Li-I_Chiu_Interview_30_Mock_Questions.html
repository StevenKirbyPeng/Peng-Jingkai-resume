09 你如何理解 Compute-in-Memory？ 研究理解
老師可能想確認：確認是否掌握實驗室核心題目。

30–45 秒回答

CIM 是把部分運算放到記憶體陣列內或附近，減少 processor 與 memory 間的大量資料搬移。對神經網路而言，主要是把權重存於 SRAM／RRAM，並在陣列中並行完成乘加或部分乘加。優勢是能效與吞吐量，挑戰是精度、資料轉換器成本、非理想效應、可程式性與系統整合。

詳細回答

傳統 Von Neumann 架構中，運算單元與記憶體分離，AI 工作負載需要反覆搬移權重與 activation。很多情況下，搬資料所消耗的時間與能量比乘加本身更高，形成 memory wall。 Compute-in-Memory 的概念，是利用 SRAM、RRAM 或其他記憶體陣列，在儲存權重的同時完成位元運算、乘法或累加。以 SRAM-CIM 為例，可以透過多列同時啟動、電流或電荷累加、時間編碼等方式得到部分 MAC 結果，再經 ADC、TDC 或數位後處理輸出。 它的優勢是高平行度、降低資料搬移與提高能效；但挑戰也很多，包括 analog non-ideality、PVT variation、ADC／DAC 面積與功耗、多位元精度、sparsity、mapping、tile 間通訊、training 支援與軟體工具。老師實驗室早期 8T SRAM-CIM 以 WBPA 與 time modulation 處理多位元精度與 converter overhead，近年則往 multi-core、multi-tile、profiler、NoC、Transformer 與 on-device learning 發展。
10 請說明老師 8T SRAM Compute-in-Memory 論文的重點。 研究理解
老師可能想確認：確認你真的讀過附件論文。

30–45 秒回答

論文以 40nm 8T SRAM 支援多位元 CNN MAC。核心方法是 Weight Bit-Partition Accumulation，降低多位元運算量化誤差與高解析資料轉換器負擔；另以 time modulation 將 DAC 數量由 n×n 降到 1。摘要報告能效約 23.5–26.3 TOPS/W。

詳細回答

這篇論文的問題是：傳統 AI accelerator 的資料搬移成本很高，而一般 SRAM-CIM 在多位元運算時又會遇到類比誤差與高解析度資料轉換器的面積、功耗問題。 它使用 8T SRAM，其中 6T 負責正常儲存，額外 2T 作為 compute port，以降低讀取／運算對儲存穩定性的干擾。輸入 feature map 透過 pulse-width 進行 time modulation，權重儲存在 SRAM cell，陣列在 bitline 上進行累加，再經 VTC、TDC 與 output combiner 形成多位元輸出。 兩個關鍵貢獻是：第一，Weight Bit-Partition Accumulation（WBPA）將多位元權重拆分，使用數位累加與多個較低解析度轉換，避免單一高解析度 converter 造成負擔；第二，time modulation 把 DAC 數量由 n×n 降到 1，改善面積與功耗。公開摘要顯示，100–400 MHz 下能效約 23.5–26.3 TOPS/W。我的理解是，它不只是提出 cell，而是同時處理精度、周邊電路與系統可用性。

一般數位 accelerator 由 SRAM buffer 搬權重與 activation 到 MAC array；CIM 則在記憶體陣列中完成部分計算。數位 accelerator 精度、可程式性與 PVT 穩定性較容易；CIM 在資料搬移與平行度上較有優勢，但受 converter、非理想效應、mapping 與校正限制。

詳細回答

一般數位 AI accelerator，例如 systolic array 或 NVDLA，會把資料從 DRAM 搬到片上 buffer，再送入 PE／MAC array。它的資料路徑與算術通常是完全數位，因此精度可控、驗證較直接，也較容易支援不同 layer 與資料格式。但即使有資料重用，buffer 與 MAC 之間仍存在大量資料移動。 CIM 將權重保留在 memory array，利用 wordline、bitline、電流、電荷或邏輯運算直接得到部分乘加結果，因此能大幅減少搬移並提高平行度。但周邊 ADC／DAC、VTC／TDC 可能佔據大量面積與功耗，類比 CIM 也受 PVT、noise、linearity 與 calibration 影響；多 tile 系統還需要 mapping、NoC、buffer 與數位後處理。 因此我不會認為 CIM 一定全面取代數位 accelerator。更實際的方向是異質整合：把適合的高密度矩陣運算交給 CIM，控制、不規則運算與高精度部分由數位核心處理。

26 什麼是 setup time、hold time？如果違反怎麼辦？ 技術基礎
老師可能想確認：檢查數位 IC 基礎。

30–45 秒回答

Setup time 是時脈有效邊緣前資料必須穩定的時間；hold time 是邊緣後仍須穩定的時間。Setup violation 可降低頻率、縮短 combinational path、加 pipeline、換快 cell；hold violation 通常在資料路徑加 delay/buffer，不能只降頻解決。

詳細回答

對一個由 flip-flop A 傳到 flip-flop B 的同步路徑，資料在 B 的 clock edge 到來前必須提早穩定至少 setup time，edge 後則需保持穩定至少 hold time。 Setup constraint 可概念化為：clock period 必須大於 clock-to-Q、combinational delay、setup time，再考慮 skew 與 uncertainty。Setup violation 表示資料太晚到，可透過降低 clock frequency、邏輯重構、使用較快 cell、減少 fanout、插入 pipeline 或改善 placement/routing。 Hold constraint關注最短路徑。Hold violation 表示新資料太快到，可能在同一 clock edge 污染下一級。通常透過加入 delay cell／buffer、調整 routing 或 clock skew 修正。單純降低 clock frequency通常無法解決 hold，因為它與相鄰同一個 edge 有關。 我也知道 RTL simulation 通常不會完整反映實體 timing，因此要靠 STA 與 gate-level／SDF 等流程檢查。
27 Blocking 與 non-blocking assignment 有什麼差別？ 技術基礎
老師可能想確認：檢查 RTL coding 基礎。

30–45 秒回答

Blocking『=』在 procedural block 中立即更新，常用於 combinational logic；non-blocking『<=』在 time step 結束統一更新，適合 sequential logic。時序 always_ff 用 <=，組合 always_comb 可用 =，避免 race 與模擬／合成不一致。

詳細回答

Blocking assignment 使用「=」，執行到該行時左值立即更新，後續敘述會看到新值，因此適合描述有順序的組合運算。Non-blocking 使用「<=」，右值在事件發生時取樣，左值在 NBA region 更新，多個暫存器可表現同一 clock edge 同時更新。 例如 pipeline register 若用 blocking，後一級可能在模擬中直接讀到前一級的新值，造成資料一個 cycle 穿透；使用 non-blocking 則各級都讀到 edge 前的舊值，符合 flip-flop 行為。 我的習慣是 clocked always_ff 中使用 non-blocking；combinational always_comb 中使用 blocking，並為所有 output 設 default assignment，避免 latch。也會避免同一 signal 被多個 block 驅動或在同一 block 混用造成 race。
28 如何驗證一個 RTL 模組是正確的？ 技術基礎
老師可能想確認：測試驗證觀念。

30–45 秒回答

先定義 specification 與 corner case；建立 reference/golden model；使用 directed＋random tests、assertion、coverage 與 scoreboard；檢查 reset、boundary、stall、backpressure；再做 lint、CDC、synthesis、STA 與必要的 gate-level 驗證。

詳細回答

第一步不是寫 testbench，而是把 specification 具體化：介面時序、reset 行為、latency、valid/ready、overflow、signedness、邊界與非法輸入。 接著建立獨立的 golden model，最好用 Python／C++ 或明確公式，避免 testbench 複製 RTL 邏輯而一起犯錯。測試包含 directed cases，例如全零、最大值、邊界、連續 valid、隨機 stall；再加入 constrained random 與 scoreboard 自動比對。 對 protocol 與內部不變量可加入 assertion，例如 valid 不可在 reset 期間為 1、request 後一定在 N cycle 回應、FIFO 不可 underflow／overflow。Coverage 用來確認 state、branch、corner 與 cross 是否被測到。 最後做 lint、CDC／RDC、synthesis warning、STA，必要時做 post-synthesis／SDF gate-level。若是 accelerator，還要比對整體數值誤差、throughput 與不同 backpressure 情況。
