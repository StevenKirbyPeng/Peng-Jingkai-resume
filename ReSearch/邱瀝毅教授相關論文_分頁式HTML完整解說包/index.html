研究方法詳解

  • 以 CASLAB-GPUSIM 為基礎的 GPGPU 平台進行系統層模擬。
  • 由 clock-gating 開關比例估算執行期 SM 核心使用率。
  • 把工作負載判定為 core-intensive 或 memory-intensive，對 SM 與 DRAM 兩個 clock domain 施行不同 DVFS。
  • 利用 FSM、可調閾值與狀態遷移抑制震盪，並整合 PLL、DC-DC converter 與 PMU。

方法論解讀

此研究不是只提出單一公式，而是將問題拆成感測／特徵取得、決策或運算核心、硬體控制、系統整合與驗證五個層次。閱讀時應特別注意：輸入訊號如何取得、控制狀態如何定義、參數如何選擇、以及基準方法是否公平。

若從 IC 與系統設計角度評估，可再檢查 critical path、記憶體存取、控制週期、額外面積、功率模型與製程／溫度／電壓變異。

主要實驗結果

  • 平均功率降低 22.3%。
  • 平均效能代價 3.2%。
  • 整體能量消耗約降低 20%。
  • 相較 DTA：DTA 雖可降功率 44.7%，但效能損失 42.1%，其平均節能僅約 4.4%。

結果詮釋

結果應同時觀察「主要目標改善」與「為此付出的代價」。例如節能方法不能只看功率下降，也要把執行時間納入能量；熱管理不能只看溫度，也要檢查效能與額外能量；安全機制需同時看攻擊成功率與硬體成本；辨識系統則應避免只呈現單一最佳案例。

研究貢獻

  • 把硬體時脈閘控資訊轉化為無需高成本軟體 profiling 的 runtime utilization 指標。
  • 針對核心域與記憶體域做異質化 DVFS，而非整顆 GPU 同步調頻。
  • 以 FSM 提升跨應用與跨架構可擴充性。

限制與可延伸方向

  • 效能與功耗來自模擬平台，實體晶片上的轉換延遲、DC-DC 效率與溫度耦合仍需驗證。
  • 利用率閾值仍需要針對平台調整；面對多 kernel 或突發型工作負載可能需更細緻預測。

後續研究建議

可將本研究放到更新的製程、實體 FPGA／ASIC／GPU 平台或更大資料集驗證，並加入跨工作負載、跨電壓溫度、長期可靠度及實際控制延遲。若是機器學習方法，也可加入可解釋性、泛化與線上學習；若是電路研究，可加入 Monte Carlo、post-layout、晶片量測與系統層應用準確率。

研究方法詳解

  • 先對宿主音訊做 DCT，選擇約 1–2 kHz 起始頻帶，以 ODG=-0.7 控制感知品質。
  • 由 Hadamard 正交矩陣及互補碼生成 PN sequences，再透過排列、互補與分層方式增加序列數與可嵌入層數。
  • 各層浮水印以 scaling factor 調整後相加，嵌入 DCT 係數，最後 IDCT 回到時域。
  • 萃取時重新 DCT，利用各層對應序列的相關性與符號函數判定浮水印位元。

研究方法詳解

  • 兩個 3-stage RV32IMC 核心分別處理一般工作與安全開機／可信任應用。
  • 安全模組含 128-bit AES-GCM、128-bit arbiter PUF 與 complete LFSR；PUF 連續評估 128 次形成金鑰。
  • 以 MPU、周邊鎖與 AHB-Lite bus matrix 隔離 user core 與安全模組。
  • FSBL 從 Boot ROM 啟動，解密與驗證 SSBL，再由 SSBL 驗證作業系統，形成 CoT。
  • 差動 arbiter PUF 搭配互補 shift registers，使功耗近似平衡，降低功耗資訊與 response 的相關性。

方法論解讀

此研究不是只提出單一公式，而是將問題拆成感測／特徵取得、決策或運算核心、硬體控制、系統整合與驗證五個層次。閱讀時應特別注意：輸入訊號如何取得、控制狀態如何定義、參數如何選擇、以及基準方法是否公平。

若從 IC 與系統設計角度評估，可再檢查 critical path、記憶體存取、控制週期、額外面積、功率模型與製程／溫度／電壓變異。

主要實驗結果

  • CRP 模型測試準確率：標準 arbiter PUF 98.95%，差動 PUF 97.325%。
  • 以 challenge–power pairs 進行旁路模型攻擊時：標準 PUF 99.175%，差動 PUF 降至 69.25%。
  • 模型攻擊準確率下降 28.85%。
  • response 與功耗相關係數降低 85.7%。

結果詮釋

結果應同時觀察「主要目標改善」與「為此付出的代價」。例如節能方法不能只看功率下降，也要把執行時間納入能量；熱管理不能只看溫度，也要檢查效能與額外能量；安全機制需同時看攻擊成功率與硬體成本；辨識系統則應避免只呈現單一最佳案例。

研究貢獻

  • 完整整合硬體安全、韌體安全、可信開機與 PUF 保護，而非僅評估單一 PUF。
  • 明確建立三條金鑰洩漏通道及其對策。
  • 以差動計算和互補暫存器抵抗功耗旁路攻擊。

限制與可延伸方向

  • PUF 穩定性、溫度／電壓漂移與 error correction 的系統成本可再完整量測。
  • 攻擊模型主要集中於 CMA-ES 與功耗相關攻擊，尚可納入更先進深度學習或電磁旁路攻擊。

後續研究建議

可將本研究放到更新的製程、實體 FPGA／ASIC／GPU 平台或更大資料集驗證，並加入跨工作負載、跨電壓溫度、長期可靠度及實際控制延遲。若是機器學習方法，也可加入可解釋性、泛化與線上學習；若是電路研究，可加入 Monte Carlo、post-layout、晶片量測與系統層應用準確率。

研究方法詳解

  • 10T2R NVSRAM cell 將 SRAM 與 RRAM 結合，支援 store／restore。
  • 提出 Nonvolatile Write Enhancement Controller（NWEC），在低壓 store 時提供額外電流。
  • 比較 SRAM 與 NV cell 資料，偵測 redundant bit；相同時取消不必要的寫入。
  • 以內建 charging-path auto-cutoff 切斷 store leakage。
  • 設計 8K-bit、8-bit I/O、68-pin test chip；採 180 nm CMOS 與研究機構 RRAM 製程。

方法論解讀

此研究不是只提出單一公式，而是將問題拆成感測／特徵取得、決策或運算核心、硬體控制、系統整合與驗證五個層次。閱讀時應特別注意：輸入訊號如何取得、控制狀態如何定義、參數如何選擇、以及基準方法是否公平。

若從 IC 與系統設計角度評估，可再檢查 critical path、記憶體存取、控制週期、額外面積、功率模型與製程／溫度／電壓變異。

主要實驗結果

  • PVT 變異下 store energy reduction 維持 87.5% 以上，最高約 91%。
  • 非冗餘位元在低壓模式相較正常模式儲存能量下降約 3.17%。
  • 冗餘位元低壓模式儲存能量下降約 46.8%。
  • 相較相關 10T2R NVSRAM，冗餘位元 store energy 降低 47.1%，非冗餘條件降低 17.6%。

結果詮釋

結果應同時觀察「主要目標改善」與「為此付出的代價」。例如節能方法不能只看功率下降，也要把執行時間納入能量；熱管理不能只看溫度，也要檢查效能與額外能量；安全機制需同時看攻擊成功率與硬體成本；辨識系統則應避免只呈現單一最佳案例。

研究貢獻

  • 把低電壓備份、寫入加強、冗餘位元偵測與自動斷流整合。
  • 對 normally-off IoT 降低 standby leakage 與 backup energy。
  • 兼顧 store time 與 store energy efficiency。

限制與可延伸方向

  • 180 nm 製程的結果不能直接代表先進節點；RRAM endurance、retention 與 variability 仍需長期量測。
  • 系統層 break-even time 與完整微處理器整合可再評估。

研究方法詳解

  • CASLAB-GPUSIM 16 SM core 平台，整合功率模型與熱模擬引擎。
  • 即時取得各核心溫度，以 hottest–coldest temperature difference 作為控制指標。
  • task dispatcher 停止向 hot cluster 發派新工作，使其完成剩餘工作後進入 clock gating。
  • 提升 cold cluster 的 V/F，承接工作並降低整體效能損失。
  • 以 workload-aware dynamic threshold 與狀態流程控制重新啟用熱核心。

方法論解讀

此研究不是只提出單一公式，而是將問題拆成感測／特徵取得、決策或運算核心、硬體控制、系統整合與驗證五個層次。閱讀時應特別注意：輸入訊號如何取得、控制狀態如何定義、參數如何選擇、以及基準方法是否公平。

若從 IC 與系統設計角度評估，可再檢查 critical path、記憶體存取、控制週期、額外面積、功率模型與製程／溫度／電壓變異。

主要實驗結果

  • 相較 baseline，平均峰值溫度降低約 13.6%。
  • 平均效能代價僅約 1.1%。
  • 平均能量額外消耗約 1.3%。
  • 能在熱安全與效能間取得較佳折衷。

結果詮釋

結果應同時觀察「主要目標改善」與「為此付出的代價」。例如節能方法不能只看功率下降，也要把執行時間納入能量；熱管理不能只看溫度，也要檢查效能與額外能量；安全機制需同時看攻擊成功率與硬體成本；辨識系統則應避免只呈現單一最佳案例。

研究貢獻

  • 把 per-core 溫度、工作排程與 cluster-level DVFS 同時納入控制。
  • 利用冷熱核心之間的空間熱差進行工作搬移。
  • 避免傳統全域降頻造成過大效能損失。

限制與可延伸方向

  • 熱模型與模擬佈局對結果影響大，實體封裝與散熱環境需要校準。
  • 工作搬移成本、cache locality 與 memory contention 可與熱控制共同最佳化。

後續研究建議

可將本研究放到更新的製程、實體 FPGA／ASIC／GPU 平台或更大資料集驗證，並加入跨工作負載、跨電壓溫度、長期可靠度及實際控制延遲。若是機器學習方法，也可加入可解釋性、泛化與線上學習；若是電路研究，可加入 Monte Carlo、post-layout、晶片量測與系統層應用準確率。

研究方法詳解

  • 以硬體監測器蒐集 GPU runtime features，作為 DDQN state。
  • action 為不同核心／記憶體電壓與頻率組合，reward 同時反映能量與效能目標。
  • CCATD 觀察每個 SM 的 memory-related task 與 cache contention，動態回報所需 task 數量。
  • 以 experience replay、target network 等 DDQN 技術訓練。
  • 另評估把 action decision／inference 放在 RISC-V CPU 上的系統 overhead。

方法論解讀

此研究不是只提出單一公式，而是將問題拆成感測／特徵取得、決策或運算核心、硬體控制、系統整合與驗證五個層次。閱讀時應特別注意：輸入訊號如何取得、控制狀態如何定義、參數如何選擇、以及基準方法是否公平。

若從 IC 與系統設計角度評估，可再檢查 critical path、記憶體存取、控制週期、額外面積、功率模型與製程／溫度／電壓變異。

主要實驗結果

  • 平均效能提升 18%。
  • 平均能量消耗降低 59%。
  • 對 compute-intensive 與 memory-intensive 程式交錯序列，能量仍可降低 53% 以上，效能損失低於 5%。
  • 顯示策略具跨工作負載適應性。

結果詮釋

結果應同時觀察「主要目標改善」與「為此付出的代價」。例如節能方法不能只看功率下降，也要把執行時間納入能量；熱管理不能只看溫度，也要檢查效能與額外能量；安全機制需同時看攻擊成功率與硬體成本；辨識系統則應避免只呈現單一最佳案例。

研究貢獻

  • 將 task dispatch 與 DVFS 聯合最佳化，而非只調頻。
  • 以 DDQN 處理非線性、跨 benchmark 的策略選擇。
  • 評估推論移至 RISC-V CPU 的可實作性與額外成本。

限制與可延伸方向

  • RL 的訓練資料覆蓋度、reward 權重與安全探索會影響泛化。
  • 真實 GPU 上的觀測延遲、控制週期與不可見狀態仍需硬體驗證。

後續研究建議

可將本研究放到更新的製程、實體 FPGA／ASIC／GPU 平台或更大資料集驗證，並加入跨工作負載、跨電壓溫度、長期可靠度及實際控制延遲。若是機器學習方法，也可加入可解釋性、泛化與線上學習；若是電路研究，可加入 Monte Carlo、post-layout、晶片量測與系統層應用準確率。
